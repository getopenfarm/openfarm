# 009-process-profiles
1. STL uploads default to a stale hardcoded "Generic PLA"/"Bambu PLA Basic" fallback (`SlicerOptions.GenericFallbackMaterialProfile` in api/src/OpenFarm.Infrastructure/Parts/SlicerOptions.cs) that no longer matches `FilamentProfile.MaterialType`'s material-category contract (e.g. "PLA") introduced by the 009 rework. Result: slicing silently fails for OrcaSlicer/Bambu Studio (`SlicingProfileUnconfiguredException`, only visible via Activity Log `PartEstimateUnavailable`), and SuperSlicer passes the bad literal straight through as an unvalidated `--filament-type` CLI flag. Fix: change the fallback values to material-category strings (e.g. "PLA") to match `RepresentativeFilamentResolver`'s matching semantics.

# 012-build-plate-selection
1. Build plate affects more than bed temperature. The real golden-file gcode fixture (`api/tests/OpenFarm.Infrastructure.Tests/Parts/Fixtures/RealSlicer/orcaslicer-2.3.1-benchy-stl/3DBenchy_PLA_35m31s.gcode`) shows the bundled slicer's own machine start-gcode conditionally branches on `curr_bed_type` for a physical nozzle Z-offset compensation too (`{if curr_bed_type=="Textured PEI Plate"} G29.1 Z{-0.04} {endif}` on Bambu Lab P1S), not just which bed-temperature field gets read. 012's spec (FR-005) only promises bed-temperature correctness; whether passing `curr_bed_type` through to the merged settings JSON is sufficient for the slicer CLI to also apply this other plate-conditional gcode itself, or whether anything else needs checking, is worth confirming during planning.
2. Job queue may want to match/filter jobs against a printer's currently selected build plate — e.g. a queued job whose part's filament requirement needs a Cool Plate (PETG/ABS) shouldn't be silently assigned to (or should be flagged against) a printer currently configured with a Textured PEI Plate. Out of scope for 012 (which only covers per-printer selection + bed-temp resolution at slice time), but worth a follow-up feature once job-queue-to-printer assignment/dispatch logic exists.
