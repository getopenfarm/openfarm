# Feature Specification: Filament Tracking

**Feature Branch**: `[006-filament-tracking]`

**Created**: 2026-07-18

**Status**: Draft

**Input**: User description: "Phase 3 Filament Tracking"

## Clarifications

### Session 2026-07-18

- Q: Should a spool reference an existing Filament (type + color variant) from a catalog, or can operators still enter ad-hoc material/color/vendor text directly on the spool? → A: Required — every spool must reference an existing Filament + color variant from the catalog; no free-text material/color entry on the spool itself.
- Q: Must a spool's starting weight be one of its Filament color variant's predefined weight options, or can operators enter any custom weight? → A: Revised — Filament color variants do not define weight options at all; the operator enters a spool's starting weight freely at spool-creation time.
- Q: Should vendor/brand stay a plain text field on Filament, or become its own separate reusable Vendor catalog entity? → A: Separate Vendor entity — Filament entries reference a manageable Vendor catalog rather than storing brand as free text.
- Q: When adding a spool, if the desired Filament/variant or Vendor doesn't exist yet, can the operator create it inline without leaving Add Spool, or must they create it separately first? → A: Separate prerequisite step — Vendor and Filament catalog entries must be created in their own management screens before they can be selected on a spool.
- Q: How should a new spool's weight be captured — a single starting-weight value, or something that also supports registering an already-partially-used spool? → A: Two fields — Spool Weight (the full/nominal weight, chosen from a predefined list of common sizes or entered manually) and Remaining Weight (defaults to equal Spool Weight, meaning a full spool, but can be lowered at creation to register a spool that's already partially used).
- Q: Should a printer's Feed Slots be created/removed by the operator, or derived strictly from what the printer's live connection reports (Multi-Material Unit slots, external spool holder)? → A: Strictly connector-derived for Multi-Material Units and the External Spool — their Feed Slots are created, updated, and deactivated automatically from the printer's reported topology; there is no manual "add feed slot" action for these, and a printer must have connected at least once before any of its Feed Slots (and therefore spool loading onto them) exist. (An Automatic Filament Reloader is the one exception — see below.) A printer's real feed configuration (how many Multi-Material Units, whether it has an external spool holder, or a mix) is only actually knowable once OpenFarm has connected to it — for example, some Multi-Material trays auto-detect their loaded material/color/brand via an RFID tag, information only available live from the connection, not something an operator could accurately declare up front.
- Q: Is the auto-continuation behavior a rename of the existing auto-reload capability, or a new physical-hardware entity? → A: **Revised below** — see the Feed Unit/Automatic Filament Reloader clarifications that follow; it is neither a simple rename nor a per-slot flag.
- Q: How should brand-specific multi-material-system terminology (e.g. Bambu's "AMS", Prusa's "MMU") be handled? → A: Feed Slots are grouped under a Feed Unit carrying a generic kind plus a unit/slot position; a brand-specific display label (e.g. "AMS 1 · Slot 2", "MMU 1 · Slot 2") is computed for display only from the printer's brand, never stored as its own column.
- Q: Should this phase also read the printer's own external/single spool holder telemetry, or keep external-spool slots out of scope for now? → A: Yes — this phase parses that telemetry too, so an External Spool Feed Unit syncs from live connectivity the same way a Multi-Material Unit does, rather than only covering multi-material printers.
- Q: A Multi-Material Unit's RFID-detected material/color/brand is already available from the live connection — should it replace, auto-suggest, or just inform which Spool the operator selects when loading that slot? → A: Validate only — the operator still explicitly selects which Spool is being loaded (RFID identifies material/color/brand, not which physical spool with however many grams remaining — an inventory distinction RFID alone can't make when multiple matching spools are in storage), but the system compares the slot's detected fields against the selected spool's Filament/color variant and raises a non-blocking warning on a mismatch.
- Q: Does every Multi-Material Unit read an RFID tag, and does an External Spool ever read one? → A: **Revised below, after research** — real hardware disproves a categorical "External Spool never reads RFID" rule; see the corrected clarification further down.
- Q: Some Automatic Filament Reloaders wire in alongside a printer's External Spool port (bypassable via a Y-connector), while others fully replace it (a multi-way splitter with no direct-feed bypass) — should the system distinguish these? → A: Yes, as an optional, advisory-only declaration. When declaring an Automatic Filament Reloader, an operator may optionally indicate it supersedes the printer's External Spool position. When set, the two are presented together rather than as unrelated accessories, and loading a spool directly onto the superseded External Spool position still succeeds but surfaces an advisory note — this is never a hard block, since the system has no way to verify actual physical wiring and shouldn't assume it can.
- Q: How is a Feed Slot organized, and can OpenFarm support a new kind of material-reload hardware later without a redesign? → A: Feed Slots are grouped under a Feed Unit — the physical accessory itself (a Multi-Material Unit, an External Spool port, an Automatic Filament Reloader, or a future kind not yet known). A Feed Unit's kind is an open, extensible classification, not a fixed closed list, so a new hardware type can be supported later without restructuring the schema.
- Q: Is "Automatic Filament Reloader" (AFR) a per-slot configuration flag, or something else? → A: It's its own Feed Unit kind — real third-party hardware (e.g. an "Infinite Flow"-style splicer) that mechanically joins a new spool's filament onto a depleted one, distinct from a Multi-Material Unit (which switches between its own trays) and an External Spool (a single port). There is no per-slot "enable auto-reload" flag and no explicit standby-spool assignment field anywhere — whether and how a Feed Unit auto-continues is determined entirely by its kind (see the next clarification).
- Q: Since an Automatic Filament Reloader is invisible to a printer's live connection (the printer's firmware has no way to report third-party splicer hardware), how does its Feed Unit get created? → A: Manually — an operator declares an Automatic Filament Reloader Feed Unit for a printer directly (naming it and how many spool positions it has), the one deliberate exception to Feed Units otherwise being strictly connector-derived. The operator must also remove/deactivate it manually, since there's no telemetry signal to detect it being disconnected.
- Q: How does a Multi-Material Unit's automatic continuation differ from an Automatic Filament Reloader's? → A: Different reload policies, matching how the real hardware behaves. A Multi-Material Unit only auto-continues when another spool already loaded elsewhere in the same unit shares the exact same Filament and color variant as the one that just depleted — it can identify what's in each of its own trays, and a non-matching or absent alternative simply means no automatic continuation (the manual path applies, same as always). An Automatic Filament Reloader auto-continues onto whatever spool is next in its own sequence regardless of material match — real splicer hardware mechanically joins filament without checking it — but still raises a mismatch warning rather than proceeding silently. An External Spool never auto-continues; it only ever has one position.
- Q: (Corrected, after researching real hardware including Snapmaker U1) Does every Multi-Material Unit read an RFID tag, and does an External Spool ever read one? → A: Neither is categorically true or false by kind. A Multi-Material Unit's RFID capability varies by brand/hardware (Bambu's AMS commonly reads it; another brand's equivalent might not), and — confirmed by real hardware, not merely theoretical — at least one real product (Snapmaker U1) reads RFID tags on individual, single-slot inputs structurally equivalent to an External Spool. Detected-material comparison therefore applies uniformly to any Feed Slot, regardless of its Feed Unit's kind: the system checks only whether that specific slot's live telemetry currently reports detected material, and skips the comparison (no warning either way) when it doesn't. This supersedes the earlier, now-disproven "External Spool never carries RFID data" rule.
- Q: Should a Multi-Material Unit's relationship to the printer's External Spool position be declared by the operator (like an Automatic Filament Reloader) or detected automatically? → A: Automatically. Unlike an Automatic Filament Reloader (invisible to any printer's connection, so it must be manually declared), a Multi-Material Unit's presence is directly observable from live telemetry. Whenever a printer reports an active Multi-Material Unit, its External Spool position is treated as implicitly secondary for display/advisory purposes — the printer's own default routes through the Multi-Material Unit unless the operator uses a bypass/multi-way connector — derived from current topology at read time, never a stored, operator-declared field like the Automatic Filament Reloader relationship.
- Q: Do multi-toolhead printers (e.g. Bambu H2D/H2C, whose filament buffer has multiple inlet ports feeding independent nozzles, confirmed to support several Multi-Material Units plus an External Spool simultaneously) need an explicit toolhead/nozzle concept on Feed Unit now? → A: Not yet — deferred. A Feed Unit already generalizes to however many physical units a printer reports, which is all this phase's inventory-tracking scope needs; which nozzle a unit ultimately routes to is a print-job routing concern for a later phase, once real per-toolhead job assignment exists.
- Q: When a Multi-Material Unit or Automatic Filament Reloader supersedes the printer's External Spool position, should the superseded position still appear in the Feed Unit listing (flagged) or be omitted entirely? → A: Omitted entirely by default — mirroring the physical reality that a printer normally has one filament input, now consumed by the superseding accessory. An operator can manually reveal it (e.g. when using a bypass/multi-way connector to genuinely use both), and it always stays visible regardless of the reveal setting whenever a spool is currently loaded on it, so an actively-tracked spool never silently disappears.
- Q: Does this hide-by-default treatment extend to additional Multi-Material Units on the same printer (e.g. a printer with 4 Multi-Material Units)? → A: No — every Multi-Material Unit stays listed normally regardless of how many exist. Multiple Multi-Material Units connected together (e.g. via an adapter) form one unified, simultaneously-selectable pool of positions — unlike a Multi-Material Unit and an External Spool, which are alternate sources for the same one physical path.
- Q: Given this phase now auto-detects when a Multi-Material Unit supersedes the External Spool, is a separate "which source is currently active for this print" concept (mirroring a printer's own per-print AMS enable/disable toggle) also needed? → A: No. That toggle controls which source a specific print job actively draws from — a job-execution-time concern this phase has no entity for (no Job exists yet). This phase's Spool state already means "physically loaded," not "currently feeding the nozzle," so two spools can be tracked as loaded (one on a Multi-Material Unit, one on a revealed External Spool) at the same time with no contradiction, regardless of which one a given print actually pulls from.
- Q: Should declaring an Automatic Filament Reloader and revealing a hidden External Spool position be two different operator actions, or one unified concept? → A: One. Both are the same underlying fact from the operator's perspective — hardware or wiring the printer's own connection can't fully account for on its own. The system presents a single "add a Feed Unit" action covering both declaring a brand-new Automatic Filament Reloader and revealing an already-detected-but-hidden External Spool position, and a matching single "remove a Feed Unit" action covering both removing an Automatic Filament Reloader and re-hiding a revealed External Spool position — an operator never needs to know these work differently underneath.
- Q: Does FR-023's automatic Multi-Material-Unit-supersedes-External-Spool treatment apply on every printer, or only ones where the two genuinely share one physical path? → A: Only single-filament-inlet printers. FR-023's premise is that a Multi-Material Unit and the External Spool position are "alternate sources for the same one physical path" — true on single-inlet printers like the Bambu A1/P1/X1 series, but not on a multi-inlet printer (e.g. Bambu H2D/H2C/X2D, whose filament buffer has multiple independent inlet ports each expandable with its own Multi-Material Unit/External Spool) where an External Spool on one inlet can be a fully independent, simultaneously-usable path unrelated to a Multi-Material Unit on another inlet. Auto-supersession MUST NOT apply on a multi-inlet printer — its External Spool positions stay listed normally regardless of Multi-Material Unit presence, the same treatment already given to a printer with multiple Multi-Material Units (previous clarification). This requires the printer catalog to know each model's filament-inlet count.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Define reusable Filament and Vendor catalog entries (Priority: P1)

As a print farm operator, I want to define the vendors I buy from and the filament types (material, color) I stock, so I have a consistent, reusable catalog to pick from whenever I log a new physical spool.

**Why this priority**: Every other story in this phase depends on this catalog existing — a spool cannot be added until its Filament and Vendor are already defined. It's independently valuable on its own too: it gives an operator a clean reference list of what materials/colors they use, even before any physical spool is logged against it.

**Independent Test**: Can be fully tested by creating a Vendor, then creating a Filament that references it with at least one color variant, and confirming both appear in their respective catalogs and the Filament's variant is selectable — all without creating a single spool.

**Acceptance Scenarios**:

1. **Given** no vendors exist yet, **When** an operator creates a new Vendor with a name, **Then** it appears in the Vendor list and can be referenced by a Filament.
2. **Given** a Vendor exists, **When** an operator creates a new Filament referencing that Vendor, with a material, material type, and at least one color variant, **Then** the Filament appears in the catalog with that variant available for future spools.
3. **Given** an operator is partway through creating a new spool, **When** the Filament/variant or Vendor they need does not yet exist, **Then** the system does not let them create it inline — they must leave Add Spool and create it in the Filament or Vendor management screen first.

---

### User Story 2 - Track a spool through its lifecycle (Priority: P1)

As a print farm operator, I want to add a new spool of filament to the system, mark it as loaded onto a printer, and mark it finished once it's depleted, so I always know what filament is on hand and what's currently in use.

**Why this priority**: This is the baseline capability the rest of the phase builds on. Simply knowing what spools exist, where they are, and whether they're available is what prevents an operator from discovering a filament shortage only when a print already needs it.

**Independent Test**: Given at least one Filament/variant already exists in the catalog (Story 1), can be fully tested by adding a spool, marking it in use on a feed slot, then removing it and marking it finished — verifying it moves through "in storage" → "using" → "finished" and is no longer offered as available inventory once finished.

**Acceptance Scenarios**:

1. **Given** no spools exist yet, **When** an operator adds a new spool by selecting an existing Filament and color variant from the catalog and entering its Spool Weight, **Then** the spool appears in inventory in the "in storage" state with its Remaining Weight defaulted to equal the Spool Weight (i.e. full).
2. **Given** an operator is adding a spool that's already partially used, **When** they lower the Remaining Weight below the entered Spool Weight before saving, **Then** the new spool is created in storage with that lower Remaining Weight rather than assuming it's full.
3. **Given** a spool in storage and a printer that has connected at least once so its Feed Slots are populated, **When** an operator marks the spool as loaded onto one of that printer's Feed Slots, **Then** the spool's state becomes "using" and it is associated with that Feed Slot.
4. **Given** a spool in the "using" state, **When** an operator removes it from its feed slot and marks it finished, **Then** the spool moves to "finished" and no longer appears as an option when loading a feed slot.
5. **Given** a spool in the "using" state with weight remaining, **When** an operator removes it but chooses to return it to storage instead of finishing it, **Then** the spool reverts to "in storage" and retains its estimated remaining weight for later use.

---

### User Story 3 - Automatic remaining-weight estimation (Priority: P2)

As an operator, I want the system to automatically estimate how much filament is left on a loaded spool based on what prints have consumed from it, so I can plan reloads without weighing every spool by hand.

**Why this priority**: This is what makes tracking useful day-to-day rather than just a manual inventory list — it directly targets running out of filament mid-print, the most common daily failure this phase exists to prevent. It's ranked after Story 1 because it only has value once spools are actually being tracked through their lifecycle.

**Independent Test**: Can be tested by loading a spool of known Remaining Weight, recording print consumption against it, and confirming the displayed remaining weight decreases accordingly; also test that a manual correction overrides the estimate.

**Acceptance Scenarios**:

1. **Given** a spool of known Remaining Weight is loaded and used across several prints, **When** an operator views the spool, **Then** the displayed remaining weight equals that starting value minus cumulative recorded consumption since it was loaded.
2. **Given** an operator believes the estimate has drifted from the spool's actual remaining weight, **When** they manually enter a corrected value, **Then** the system uses the corrected value going forward.

---

### User Story 4 - Automatic continuation on Multi-Material Units and Automatic Filament Reloaders (Priority: P3)

As an operator running an unattended setup, I want a depleted spool to automatically hand off to another already-loaded spool without me being physically present, so an unattended print run doesn't stall just because one spool ran out.

**Why this priority**: Highest automation value, but it only applies once a printer has connected and reported its Multi-Material Unit's Feed Slots (or an operator has manually declared an Automatic Filament Reloader), so this behavior is fully buildable now, gated on that having happened, not on any later phase.

**Independent Test**: Can be tested by loading two spools of the same Filament/color into different positions of a connected printer's Multi-Material Unit, driving cumulative usage on the active one until its estimated Remaining Weight reaches zero, and confirming the system automatically marks it finished and continues from the other spool; separately test that a Multi-Material Unit with a differently-matched (or no) second spool does *not* auto-continue; and separately test a manually-declared Automatic Filament Reloader's unconditional continuation, including its own mismatch-warning path.

**Acceptance Scenarios**:

1. **Given** a Multi-Material Unit with two loaded spools sharing the same Filament and color variant, **When** the active one's estimated Remaining Weight reaches zero from recorded usage, **Then** the system marks it finished and continues from the other already-loaded spool automatically, with no operator action required.
2. **Given** a Multi-Material Unit whose active spool depletes with no other loaded spool sharing its Filament/color variant, **When** that threshold is reached, **Then** the system does not auto-continue — the manual mark-finished path applies, the same as any Feed Slot with nothing to continue onto.
3. **Given** an Automatic Filament Reloader with a second spool loaded in its next position, **When** its active spool's estimated Remaining Weight reaches zero, **Then** the system continues from that next spool automatically regardless of whether its Filament/color matches.
4. **Given** the Automatic Filament Reloader's next spool's material/color differs from the one that just depleted, **When** the automatic continuation occurs, **Then** it still completes, but a warning is raised on the dashboard and recorded against the affected job.

---

### Edge Cases

- What happens when cumulative recorded usage exceeds a spool's Remaining Weight (estimate would go negative)? Remaining Weight should floor at zero rather than go negative, and the spool should be flagged for the operator to confirm.
- How does the system handle an operator marking a spool finished while a significant amount of weight is still estimated remaining (e.g., a deliberate color change mid-job, not a true depletion)?
- What happens when a Multi-Material Unit's active spool depletes but no other spool loaded in that unit shares its Filament/color variant? The system should treat it the same as an External Spool depleting with nothing to continue onto — the manual mark-finished path applies, not a warning, since this is an ordinary, expected outcome of the match requirement rather than a fault.
- What happens when an Automatic Filament Reloader's active spool depletes but no other spool is loaded in its next position at all? The system should raise a visible warning rather than fail silently, since unattended continuation isn't possible and, unlike a Multi-Material Unit, an Automatic Filament Reloader's whole purpose is to continue regardless of match.
- What happens when an operator tries to manually declare a second Automatic Filament Reloader for the same printer, or remove one that still has a spool loaded in one of its positions? The system should still allow the declaration (a printer could plausibly have more than one), but removing/deactivating one with an actively-loaded spool should behave the same as a Multi-Material Unit losing telemetry mid-use (Edge Case above): the spool's own state/history stays undisturbed, only the Feed Unit/Slots become unavailable for new loads.
- What happens when an External Spool position is hidden by default (superseded by a Multi-Material Unit or Automatic Filament Reloader) but a spool is already loaded on it — e.g. left over from before the superseding accessory was attached, or loaded via a bypass connector the operator never explicitly revealed? It stays visible in the Feed Unit listing regardless of the hidden/revealed state — hiding never applies to a position with an actively-loaded spool.
- What happens if two operators attempt to change the same spool's state at the same time? The system should apply one change and reject or ignore the conflicting concurrent change rather than corrupt the spool's state.
- What happens when an operator tries to enter a zero, negative, or non-numeric Spool Weight or Remaining Weight for a new spool? The system should reject it and require a positive value before the spool can be created.
- What happens when an operator tries to set a new spool's Remaining Weight higher than its Spool Weight? The system should reject it — Remaining Weight can never exceed the spool's full (Spool Weight) capacity.
- What happens when an operator tries to add a spool but the Filament, color variant, or Vendor they need doesn't exist in the catalog yet? The Add Spool flow cannot offer it as a selection — the operator must first create the missing Filament/variant or Vendor in its own management screen, then return to Add Spool.
- What happens when a printer's reported topology changes while one of its Feed Slots is actively "using" a spool (e.g. a Multi-Material Unit is physically unplugged mid-print)? That Feed Slot is deactivated from future selection, but it isn't deleted and the spool's own state/history is undisturbed — the spool stays "using" until the operator removes it.
- What happens when an operator tries to load a spool onto a printer that has never connected? The system should reject it — no Feed Slot exists yet for that printer to load onto.
- What happens when a Feed Slot's detected material/color doesn't match the Filament/color variant of the spool an operator selects to load onto it (any Feed Unit kind, not only Multi-Material Units — detection capability varies by product, confirmed by real hardware research)? The system should still complete the load (detection isn't always available or reliable) but raise a non-blocking warning rather than silently proceeding or blocking the load outright.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST allow operators to add a new spool by selecting an existing Filament and color variant from the catalog and entering a Spool Weight (the full/nominal weight, chosen from a predefined list of common sizes or entered as a custom value) — a spool MUST NOT be creatable with free-text material/color/vendor entry.
- **FR-002**: System MUST default a new spool's Remaining Weight to equal its Spool Weight (a full spool) unless the operator lowers it at creation time to register a spool that's already partially used.
- **FR-003**: System MUST NOT require a physical barcode or other unique identifier to add or use a spool.
- **FR-004**: Every spool MUST be in exactly one of three states at any time: in storage, using, or finished.
- **FR-005**: System MUST allow an operator to move a spool from in storage to using by assigning it to a specific feed slot.
- **FR-005a**: System MUST create, update, and deactivate a Multi-Material Unit's or External Spool's Feed Unit/Feed Slot records automatically from that printer's live connection reporting its real topology — operators MUST NOT be able to manually create, rename, or delete these Feed Slots.
- **FR-005b**: System MUST NOT allow a spool to be loaded onto a printer that has never connected, for Feed Slots belonging to a connector-derived Feed Unit — those Feed Slots do not exist until the printer's first successful connection.
- **FR-005c**: System MUST allow an operator to manually add an Automatic Filament Reloader Feed Unit for a printer — including how many spool positions it has — since this hardware is not visible to any printer's live connection, and MUST allow the operator to remove it manually as well, using the same single "add/remove a Feed Unit" action FR-024 uses for revealing/re-hiding an External Spool position.
- **FR-006**: While a spool is in the using state, system MUST automatically estimate its Remaining Weight from recorded print consumption, starting from the Remaining Weight it had when loaded.
- **FR-007**: When an operator removes a spool from a feed slot, system MUST display its current estimated Remaining Weight and let the operator choose to return it to storage or mark it finished.
- **FR-008**: System MUST NOT automatically mark a spool finished based on estimated weight alone unless FR-009's conditions are met for that Feed Slot's Feed Unit — otherwise, marking a depleted spool finished MUST always be a manual operator action.
- **FR-009**: When a spool's estimated Remaining Weight reaches zero from recorded usage, system MUST automatically mark it finished and continue printing from another already-loaded spool without requiring operator action when: (a) its Feed Slot belongs to a Multi-Material Unit and another spool loaded elsewhere in that same unit shares the exact same Filament and color variant as the depleted one; or (b) its Feed Slot belongs to an Automatic Filament Reloader and another spool is loaded in that unit's next position, regardless of material match. A Feed Slot belonging to an External Spool MUST NOT auto-continue — it has no other position to draw from.
- **FR-010**: A Multi-Material Unit MUST NOT auto-continue onto a spool whose Filament/color variant differs from the one that just depleted — no matching spool loaded elsewhere in the unit MUST be treated the same as nothing being loaded there at all (FR-008's manual path applies).
- **FR-011**: When an Automatic Filament Reloader auto-continues onto a spool whose Filament/color variant differs from the one that just depleted, system MUST still complete the continuation, but MUST raise a visible warning on the dashboard and record the mismatch against the affected job.
- **FR-011a**: System MUST determine whether and how a Feed Unit auto-continues purely from its kind — no separate per-slot or per-unit "enable auto-continue" setting or standby-spool assignment field exists.
- **FR-012**: System MUST allow an operator to manually override a spool's system-estimated Remaining Weight at any time.
- **FR-013**: System MUST allow a Filament catalog entry to exist and be selected onto a spool without being linked to any imported slicer/machine profile (Phase 2) — that linkage stays optional and separate from spool tracking.
- **FR-014**: System MUST record every spool state transition (in storage, using, finished) in the activity log, including who made the change and when.
- **FR-015**: System MUST allow operators to view the list of spools filtered by state, filament, color, and vendor.
- **FR-016**: System MUST allow operators to create and manage reusable Filament catalog entries (material, material type, Vendor reference, color variants) independently of adding spools, so the same entry can be selected across many spools.
- **FR-017**: System MUST allow operators to create and manage reusable Vendor entries independently, so a Vendor can be selected on a Filament entry instead of retyped as free text.
- **FR-018**: The Add Spool flow MUST only offer Filament/variant and Vendor selection from what already exists in their catalogs — it MUST NOT allow creating a new Filament, variant, or Vendor from within that flow; missing entries must be created in their own management screens first.
- **FR-019**: System MUST represent a Feed Unit's kind as an open, extensible classification (Multi-Material Unit, External Spool, Automatic Filament Reloader, and any future kind) rather than a fixed, closed list, and MUST compute a brand-appropriate display label (e.g. "AMS", "MMU") for a Multi-Material Unit from the printer's brand only for display purposes — never persisted as its own field.
- **FR-020**: For printer brands whose live connection reports an external/single spool holder (in addition to any Multi-Material Unit telemetry), system MUST parse that telemetry too, so an External Spool Feed Unit syncs from live connectivity the same way a Multi-Material Unit does.
- **FR-021**: When an operator loads a spool onto a Feed Slot whose live connection currently reports detected material/color/brand for that position — regardless of its Feed Unit's kind — system MUST compare the detected values against the selected spool's Filament/color variant and surface a non-blocking warning on a mismatch — the load MUST still complete regardless of the comparison's outcome. A Feed Slot with no currently-detected material MUST skip the comparison (no warning either way) rather than assume detection failed or the position is empty; this applies uniformly across kinds, since detection capability is a hardware fact confirmed to vary by product, not something implied by a Feed Unit's kind.
- **FR-022**: System MUST allow an operator, when declaring an Automatic Filament Reloader, to optionally indicate that it supersedes the printer's External Spool position. When declared, the External Spool position MUST be omitted from the default Feed Unit listing (mirroring the physical reality that its one input is consumed by the Automatic Filament Reloader) unless revealed (FR-024) or currently holding a loaded spool (FR-025) — it MUST NOT be a hard restriction on loading directly onto it.
- **FR-023**: Whenever a printer has an active Multi-Material Unit **and the printer model has a single filament inlet** (FR-023a), system MUST automatically apply the same treatment to its External Spool position — omitted from the default Feed Unit listing by default, without requiring an operator declaration (unlike FR-022's Automatic Filament Reloader case), since a Multi-Material Unit's presence is directly observable from the printer's live connection. This determination MUST NOT extend to additional Multi-Material Units on the same printer — every Multi-Material Unit remains listed normally regardless of how many exist, since multiple Multi-Material Units connected together form one unified, simultaneously-usable pool of positions rather than alternate sources for the same one path the way a Multi-Material Unit and an External Spool are.
- **FR-023a**: System MUST NOT apply FR-023's automatic supersession on a multi-inlet printer model (one whose filament buffer has more than one independent inlet port, e.g. Bambu H2D/H2C/X2D) — a Multi-Material Unit on one inlet and an External Spool on another are independent, simultaneously-usable paths there, not alternate sources for one shared path. This requires the printer catalog to record each model's filament-inlet count. On a multi-inlet printer, an External Spool position is never auto-hidden by Multi-Material Unit presence; it MAY still be hidden if an operator has declared an Automatic Filament Reloader superseding it directly (FR-022), since that relationship is explicit per-position, not inlet-topology-driven.
- **FR-024**: System MUST let an operator reveal an otherwise-hidden External Spool position (FR-022/FR-023) — for example, when a bypass/multi-way connector makes it genuinely usable alongside whatever supersedes it — and re-hide it later, through the same single "add a Feed Unit" / "remove a Feed Unit" action used to declare and remove an Automatic Filament Reloader (FR-005c). An operator MUST NOT need to know that revealing an already-detected External Spool and declaring a brand-new Automatic Filament Reloader work differently underneath — both are "add a Feed Unit"; re-hiding and removing an Automatic Filament Reloader are both "remove a Feed Unit." Revealing/re-hiding MUST NOT affect any other Feed Unit's kind, auto-continuation behavior, or existence — it only affects whether this one position appears in the default Feed Unit listing.
- **FR-025**: Regardless of whether an External Spool position is currently hidden (FR-022/FR-023) or not yet revealed (FR-024), system MUST still include it in the Feed Unit listing whenever a spool is currently loaded onto it — an actively-tracked spool MUST NOT become invisible, even if "remove a Feed Unit" was used to re-hide it.
- **FR-026**: When an operator uses the "add a Feed Unit" action to reveal an External Spool position that the printer's live connection has never actually reported, system MUST reject the action — there is nothing to reveal.

### Key Entities

- **Spool**: A single physical roll of filament tracked by the system — the *instance*. Key attributes: current state (in storage/using/finished), Spool Weight (full/nominal capacity), Remaining Weight (defaults to Spool Weight at creation, then estimated automatically while in use), assigned feed slot (only while using), and a required reference to the Filament + color variant it contains.
- **Filament**: The reusable catalog entry describing a *type* of filament — a reference to its Vendor, material name, material type, and one or more color variants. A Filament exists independently of any spool and may optionally link to an imported slicer/machine profile (Phase 2), but doesn't require one; it does not carry weight information — that's recorded per spool.
- **Vendor**: The manufacturer/brand of a Filament — its own reusable catalog entry (e.g. name), referenced by one or more Filament entries rather than retyped as free text on each.
- **Feed Unit**: The physical accessory that hosts one or more Feed Slots — a Multi-Material Unit (Bambu's AMS, Prusa's MMU, etc.), an External Spool port, or an Automatic Filament Reloader (a third-party splicer). Its kind is an open, extensible classification, not a fixed closed list. A Multi-Material Unit and an External Spool are synced automatically from the printer's live connection reporting its real topology — never created, renamed, or removed manually, and not existing until the printer has connected at least once. An Automatic Filament Reloader is the one exception: it's invisible to any printer's live connection, so an operator adds it manually (naming it and how many spool positions it has) and removes it manually too. When adding one, an operator may optionally indicate it supersedes the printer's External Spool position (some are wired to fully replace it rather than sit alongside it via a bypassable connector). A Multi-Material Unit's relationship to the External Spool position is the same, but never needs a manual declaration — since the Multi-Material Unit's presence is directly observable from live telemetry, the system automatically detects it whenever one is active. Either way, a superseded External Spool position is omitted from the default Feed Unit listing entirely — mirroring the physical reality that a printer normally has one filament input, which the superseding accessory has taken over — unless the operator reveals it (indicating they're using a bypass/multi-way connector to use both) or a spool is currently loaded on it, in which case it always stays visible regardless. This never blocks loading a spool directly onto it. This superseding relationship never applies between multiple Multi-Material Units on the same printer — they form one unified, simultaneously-usable pool of positions, not alternate sources for the same path. Adding a brand-new Automatic Filament Reloader and revealing an already-detected-but-hidden External Spool position are the same single operator action ("add a Feed Unit"), and removing an Automatic Filament Reloader and re-hiding a revealed External Spool position are likewise the same single action ("remove a Feed Unit") — an operator never needs to know these behave differently underneath.
- **Feed Slot**: A single loading position within a Feed Unit where a spool is mounted while in use — e.g. one tray of a Multi-Material Unit, the sole position of an External Spool, or one position of an Automatic Filament Reloader. A Feed Unit's brand-specific display label (e.g. "AMS 1 · Slot 2") is computed for display from the printer's brand and the unit's generic kind/position, never stored as its own field. Whether and how a Feed Slot's Feed Unit automatically continues onto another spool when one depletes is determined entirely by the Feed Unit's kind — there is no separate per-slot or per-unit "enable auto-continue" setting and no standby-spool assignment field.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: An operator can register a new spool with all required details in under 30 seconds.
- **SC-002**: An operator can determine any spool's current state and estimated remaining weight at any time without physically inspecting or weighing it.
- **SC-003**: Unplanned mid-print stoppages caused by a tracked spool running out unexpectedly drop by at least 90% compared to not tracking spools at all.
- **SC-004**: On Feed Slots whose Feed Unit qualifies to auto-continue (a Multi-Material Unit with a matching spool already loaded elsewhere in the unit, or an Automatic Filament Reloader with a next spool loaded), an unattended print run continues across a spool depletion event without operator intervention in at least 95% of cases.
- **SC-005**: 100% of spool state transitions are retrievable afterward in the activity/audit history.

## Printer-detail presentation refinement — 2026-10-05

- The printer detail page presents one **Feed Units** card combining the live AMS monitoring required by Spec 002 FR-008 with this feature's grouped topology and registered inventory. There is no separate “Filament — AMS” card.
- Units retain their brand-aware labels; each slot appears once. Registered filament identity and tracked remaining grams remain distinct from detected material/brand/color and printer-reported remaining percentage. Detected contents without an inventory assignment are labelled unregistered; only explicit empty telemetry means “Empty.” Missing telemetry means detection unavailable.
- Active feeding is a read-only telemetry indicator, never a source-selection control or a synonym for a spool's `Using` inventory state. Offline detection is labelled last known, active indication is suppressed, and deactivated slots retain their registered inventory with an inactive label.
- The frontend combines existing responses by unit index and slot position without changing REST, hub, or database contracts. First telemetry and subsequent AMS topology changes refresh that printer's Feed Units query; ordinary material/activity/percentage updates render from the live printer-detail cache without repeated requests.
- Loading, failure with retry, and a successfully empty topology have distinct presentations. Existing Add/Remove Feed Unit actions and FR-022–FR-025 visibility rules continue to apply. Spool loading/unloading controls remain in their existing workflows.

## Assumptions

- Spool identification is entirely manual (an operator-chosen label); physical barcode/unique-ID scanning is explicitly out of scope for this phase and deferred to a later optional-identification phase.
- A spool's Filament (type + color variant) is required at creation, but linking that Filament to an imported slicer/machine profile (Phase 2) is optional — a Filament catalog entry, and any spool made from it, can be added and tracked through in storage/using/finished with no profile attached; a profile only matters once the spool is actually consumed by a job.
- The automatic-continuation behaviors (FR-009 through FR-011a) are fully buildable in this phase — for a Multi-Material Unit, gated only on the target Feed Slot existing (i.e. its printer having connected and reported it, per FR-005a/b); for an Automatic Filament Reloader, gated only on the operator having manually declared it (FR-005c) — not deferred to a later phase. Absent a qualifying match/next spool, a Feed Slot follows the manual mark-finished path (FR-008) by default.
- Remaining-weight estimation depends on recorded print/job filament consumption existing somewhere in the system, even though the full job entity is formalized in a later phase; some interim or partial usage-recording mechanism is assumed to feed this estimate in the meantime.
- Vendor and filament material/color entries are reusable catalog values scoped to the operator's organization, not shared globally across organizations.
- Catalog/inventory management — creating Vendors, Filaments, and registering a spool into the "in storage" state (User Story 1, and the in-storage portion of User Story 2) — requires no live printer connection. Loading a spool onto a Feed Slot, and everything downstream of that (the "using" state, remaining-weight tracking while in use, Automatic Filament Reloader continuation), requires the target printer to have connected at least once so its Feed Slots exist (FR-005a/b) — a deliberate narrowing from an earlier assumption that the entire spool lifecycle needed zero printer knowledge. Beyond that connectivity requirement, behavior is still identical across printer brands/models — no functional logic branches on brand or Feed Unit kind beyond computing a Feed Slot's display label (FR-019) and, where a specific Feed Slot's connection reports it, detected material/color (FR-021, confirmed not exclusive to any one kind).
- Multi-toolhead printers (multiple inlet ports feeding independent nozzles) are supported at the same granularity as any other printer — however many Feed Units and Feed Slots a printer's connection reports, tracked identically — but no toolhead/nozzle-routing concept exists in this phase; that's deferred until a later phase needs to assign jobs per toolhead.
- A printer's own per-print "which source is actively feeding the nozzle" toggle (e.g. enable/disable a Multi-Material Unit for a specific print) is out of scope for this phase — it's a job-execution-time concern with no entity to attach it to yet (no Job exists). This phase only tracks which spool is physically loaded where, not which loaded spool a given print is actually drawing from.
